Modern Protocol, New Risks

HTTP/2 improves performance with multiplexed streams and a single connection, but that same efficiency can be abused by attackers seeking asymmetric resource exhaustion.

What is HTTP/2?

HTTP/2 is the current standard for web transport. It replaces plain text request/response streams with a binary framing layer, enabling multiple requests to share one TCP/TLS connection.

Key advantages include:

  • Multiplexing many streams concurrently over a single connection.
  • Header compression to reduce overhead and latency.
  • Stream prioritization and flow control for faster page delivery.

These properties make HTTP/2 powerful for normal traffic, but also open the door to novel asymmetric attacks when a single client can create outsized server cost.

What is the DDoS Rapid Reset attack?

The Rapid Reset attack targets HTTP/2 connections by creating many streams and then resetting them quickly. Each reset forces the server to clean up state and may trigger expensive connection or stream resource work.

Because HTTP/2 supports many active streams on one connection, attackers can generate high load with relatively little bandwidth, making the attack asymmetric.

  • Attackers open numerous HTTP/2 streams.
  • They send many RST_STREAM frames or abort streams rapidly.
  • The server must allocate and free resources for each reset, which can exhaust memory and processing capacity.

What we are building

This project is a research prototype that connects the Linux kernel packet queue to a user-space C program using NFQUEUE. It is designed to inspect HTTPS traffic intelligently without disrupting the web server.

Instead of building a complete detection engine yet, the current focus is on:

  • Capturing HTTPS packets at the kernel level.
  • Passing them to a C daemon for analysis.
  • Returning a verdict that preserves normal traffic flow.

That foundation will make it possible to layer real HTTP/2 attack detection later.

Why this matters

Modern server applications depend on HTTP/2 for performance, but the protocol also presents new attack surfaces. Rapid Reset and similar asymmetric DoS attacks can target the efficiency mechanisms themselves.

The reason for this research is to create a defensible interception layer that can later distinguish malicious HTTP/2 behavior from legitimate traffic, while allowing secure TLS connections to continue uninterrupted.

  • Protect web servers from stealthy, state-exhausting attacks.
  • Retain compatibility with normal HTTPS application traffic.
  • Provide a realistic prototype for future HTTP/2 anomaly detection.
